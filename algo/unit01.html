01資料、資訊與演算法

資料 (Data)：未經處理的原始記錄，例如某位學生的各科原始成績。

資訊 (Information)：經過整理、計算、分析後，對決策者有意義的結果，例如全班的排名與分佈圖。

演算法（Algorithm）就是「解決問題的一連串明確步驟」——它不是程式碼本身，而是程式碼背後的邏輯。同一個演算法，可以用 Python 寫、也可以用 C++ 寫，這也是這個課程從頭到尾都給你兩種語言對照的原因。

02演算法的五個必要條件

  • 輸入 (Input)：可以是 0 個或多個。
  • 輸出 (Output)：至少要有一個。
  • 明確性 (Definiteness)：每一步都必須清楚，不可模稜兩可。
  • 有限性 (Finiteness)：必須在有限步驟內結束（真正的程式可以寫無窮迴圈，但「演算法」不行）。
  • 正確性 (Correctness)：符合前面四點不代表正確，邏輯本身要能真正解決問題。
⚠ 常見誤解

很多人以為「程式能執行、不會當機」就是好的演算法，但「明確性」跟「正確性」是兩回事——程式可能會跑，但答案是錯的。寫完程式之後，養成用不同測試資料驗證答案的習慣非常重要。

03時間複雜度 Time Complexity

時間複雜度是用大 O 符號描述「演算法執行次數」隨資料量成長的速度，跟電腦實際跑多快（硬體、程式語言）沒有直接關係，重點是「成長趨勢」。

記法唸法意義例子
O(1)常數時間跟資料量無關，永遠差不多快取陣列第 0 個元素
O(log n)對數時間每次都把範圍砍半二分搜尋
O(n)線性時間資料量變 2 倍，時間也變 2 倍從頭找到尾
O(n log n) 恩肉格恩

正式唸法：線性對數時間

目前已知排序最好的等級合併排序、快速排序（平均）
O(n²)平方時間資料量變 2 倍，時間變 4 倍氣泡排序、選擇排序
🎬 經典例子：租片店 vs 網路下載

租片店：不管店裡有幾萬部片，走路過去單程都是 25 分鐘、來回 50 分鐘——這是 O(1)，跟資料量（片庫大小）完全無關。
網路一部一部下載：每部片下載要 3 分鐘（現在的網路速度），這是 O(n)，資料量變大，時間就跟著等比例變大。

五種時間複雜度，各自的程式範例

O(1) 常數時間：直接用索引取值

O(1) 常數時間：直接用索引取值 
arr = [10, 20, 30, 40, 50]
print(arr[0])          # 不管 arr 有幾個元素，永遠只做這一步
print(arr[-1])

O(n) 線性時間：單層迴圈跑 n 次

O(n) 線性時間：單層迴圈跑 n 次 
n = 1000000
total = 0
for i in range(n):      # 單層迴圈跑 n 次 → O(n)
    total += i
print(total)

O(n²) 平方時間：兩層巢狀迴圈

O(n²) 平方時間：兩層巢狀迴圈 
n = 1000
count = 0
for i in range(n):          # 外層跑 n 次
    for j in range(n):        # 內層也跑 n 次
        count += 1
print(count)                  # 總共執行 n × n 次

O(log n) 對數時間：二分搜尋，每次砍半

👀 先偷看一下程式碼

這裡的「二分搜尋」會在後面的單元才正式教，這裡只是先讓大家知道 O(log n) 長什麼樣子，看不懂沒關係。

O(log n) 對數時間：二分搜尋，每次砍半 
def binary_search(a, key):
    left, right = 0, len(a) - 1
    while left <= right:
        mid = (left + right) // 2
        if a[mid] == key:
            return mid
        elif a[mid] < key:
            left = mid + 1
        else:
            right = mid - 1
    return -1

O(n log n)：合併排序（切一半、分別排序、再合併）

👀 先偷看一下程式碼

這裡的「合併排序」也是後面排序單元才會教的演算法，先看過一次眼熟就好。

O(n log n)：合併排序（切一半、分別排序、再合併） 
def merge_sort(a):
    if len(a) < 2:
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])     # 切一半，遞迴排序
    right = merge_sort(a[mid:])
    return merge(left, right)       # 合併兩個排好的部分

def merge(left, right):
    result = []
    while left and right:
        result.append(left.pop(0) if left[0] < right[0] else right.pop(0))
    return result + left + right

✏️ 練習：判斷時間複雜度（依速度由快到慢排列）

  1. 這段程式的時間複雜度是多少？
    python
    scores = [88, 92, 76, 65, 99]
print(scores[0])
print(scores[-1])

    ▸ 看答案

    O(1)。不管 scores 裡面有幾個元素，這段程式永遠只執行「固定 2 行」，取第一個、取最後一個都是直接用索引定位，跟資料量 n 完全無關。

  2. 這段程式的時間複雜度是多少？
    python
    for x in range(m):
    for y in range(m):
        print(x, y)

    ▸ 看答案

    O(m²)。兩層迴圈互相巢狀，外層跑 m 次、每次內層又跑 m 次，總共 m × m 次（跟資料量的字母是 n 還是 m 沒有關係，看的是巢狀的層數）。

  3. 這段程式的時間複雜度是多少？（提示：內層迴圈執行的次數，每一輪都不一樣）
    python
    for a in range(k):
    for b in range(a):
        print(a, b)

    ▸ 看答案

    O(k²)。雖然內層迴圈執行次數不是每次都固定是 k（第 a 輪只跑 a 次：0+1+2+…+(k-1)），但把這些次數全部加起來大約是 k²/2——省略係數跟低次項之後，時間複雜度仍然算 O(k²)，跟寫成 range(k) 是同一個等級。這是很多人會誤判成 O(k) 的地方，要特別小心（雖然跟上一題同樣是平方等級，但這題的迴圈次數不是一眼就能看出來的，要特別留意）。

01非對稱加密：兩把不一樣的鑰匙

對稱式加密最大的痛點：雙方要先用安全管道交換同一把 key，而且每多一個通訊對象，就要多管理一把 key。公開金鑰加密系統（非對稱式加密）解決了這個問題：每個人有一對數學上相關、但不能互相推算的鑰匙 —— 公開金鑰（公鑰）可以公開給所有人，私有金鑰（私鑰）則自己保密收好。

🔁 回扣比特幣

還記得單元 5 說「私鑰可以簽署交易、公鑰算出地址」嗎？這裡就是它背後的數學原理：用私鑰簽章、用公鑰驗證，正是非對稱加密最經典的應用之一。

02RSA：怎麼產生這兩把鑰匙

RSA 金鑰產生演算法 
1. 選擇兩個大質數 p, q
2. 計算 n = p × q
3. 計算 φ(n) = (p-1) × (q-1)
4. 找出一組 e、d，滿足 e × d ≡ 1 (mod φ(n))
5. 公開 (e, n) 當作公鑰；(d, n) 保密當作私鑰
🧮 動手跟著算一次（課本範例）
步驟數值
選質數p = 241，q = 311
計算 nn = p × q = 74951
計算 φ(n)φ(n) = 240 × 310 = 74400
選 ee = 1033（需與 φ(n) 互質）
算出 dd = 3097（e 的模反元素）
公鑰 / 私鑰公鑰 (e, n) = (1033, 74951)　／　私鑰 (d, n) = (3097, 74951)
RSA 簽章與驗證範例 
簽章：對明文 m = 38（假設是某段訊息的編碼）
  s = m^d mod n = 38^3097 mod 74951 = 12735

驗證：用公鑰 (e, n) 檢查
  m =? s^e mod n
  38 =? 12735^1033 mod 74951　→ 成立，驗證通過！

大數字的次方 mod 運算，可以用線上工具幫忙算：大數計算機 ↗、模反元素計算工具 ↗。

03為什麼安全：反推 d 幾乎不可能

公鑰 (e, n) 是公開的，任何人都知道。理論上如果能把 n 分解回 p × q，就能算出 φ(n)，進而算出私鑰 d —— 但當 p、q 是幾百位數的大質數時，大數質因數分解用現有電腦要花的時間長到不切實際。這正是 RSA 安全性的數學基礎。

RSA 的數字範例比較硬，可以挑一種節奏：

🅰️ 老師帶算 + 線上工具驗證

老師在台上帶著全班一步步算過 p、q → n → φ(n) → e、d，卡住的地方（大數次方 mod）直接用線上計算機驗證，重點放在「流程看得懂」而非手算能力。

🅱️ 小組任務：換一組更小的質數自己算

把全班分組，每組拿到一組更小的質數（例如 p=7, q=13），自己走一遍金鑰產生 → 簽章 → 驗證的流程，最後互相驗證別組的簽章，體會「公鑰誰都能驗證，但只有私鑰持有人能簽出正確簽章」。

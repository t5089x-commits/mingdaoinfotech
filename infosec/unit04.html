區塊鏈是什麼

區塊、鏈結、不可竄改 —— 比特幣、交易所、Web3.0 背後的共同技術

🎯 學習目標

  • 知道區塊鏈技術目前實際應用在哪些地方
  • 理解區塊（block）、鏈結（chain）如何組成區塊鏈
  • 認識雜湊（hash）如何讓資料「不可竄改」
  • 透過 Merkle Tree 的概念，理解如何有效驗證大量資料的完整性
  • 認識雜湊在密碼儲存上的實際應用

01區塊鏈技術，其實已經用在很多地方

「區塊鏈」聽起來很技術，但它其實已經是很多你聽過、甚至用過的東西背後的共同基礎。在拆解技術細節之前，先看看它目前實際應用在哪些地方：

應用領域簡單說明
虛擬貨幣（比特幣、以太幣…）用區塊鏈記錄「誰的錢包裡有多少錢」，不需要銀行就能公開驗證每一筆交易（下一個單元會細講）。
虛擬貨幣交易所讓使用者買賣、兌換虛擬貨幣的平台；交易所本身是中心化服務，但背後真正決定「誰擁有多少資產」的，仍然是區塊鏈上的公開帳本。
Web3.0 應用（DApp）「使用者自己掌握資料與資產」的網路服務，就是架在區塊鏈這個底層帳本之上（回顧單元 2）。
智能合約／DeFi把借貸、交易等金融行為直接寫成程式碼、放到區塊鏈上自動執行，不需要中介機構（單元 6 會細講）。
履歷／憑證存證想證明某項資料「從某個時間點起沒有被偷改過」的場景，例如商品履歷溯源、學歷或證書驗證。

看完這個表格，這學期你只需要先記住一句話：區塊鏈的核心價值，是讓「一群互不信任的人」也能公開驗證同一份資料沒有被動過手腳。接下來就來看看它實際上是怎麼做到的。

02區塊鏈的基本組成

區塊鏈（blockchain）是一系列經過驗證的區塊組成的列表，每個區塊都鏈接到它的前一個區塊，一直往前追溯到第一個區塊（創世區塊 genesis block）。

每個區塊都在自己的區塊頭裡，記錄「前一個區塊的雜湊值」，一路串成一條鏈。

🧱 區塊頭 Block Header

記錄「上一個區塊的雜湊值」等中繼資料，就是這個「鏈」的接點。

📦 區塊體 Block Body

放實際的資料（例如一批交易記錄），以 Merkle Tree 的形式組織。

🔗 為什麼「串起來」就不可竄改？

因為每個區塊的區塊頭裡都放了「前一個區塊的雜湊值」。只要有人偷改了前面任何一個區塊的內容，它的雜湊值就會整個改變，後面所有區塊記錄的「前一個雜湊值」就對不上了 —— 就像骨牌一樣，一改就全部露餡。

03Merkle Tree：怎麼快速驗證資料沒被動過手腳

想像你要下載一個 8GB 的大檔案，要怎麼確認下載下來的檔案完全正確、沒有任何一個位元組被竄改？

笨方法：把整個 8GB 從頭到尾重新雜湊一次比對 —— 慢，而且只要錯一個位元組，你完全不知道是哪裡錯。

Merkle Tree 的做法：把檔案切成很多小區塊，每個小區塊各自算一個雜湊值，再兩兩配對、一層層往上算雜湊，最後得到一個「Merkle root」。

步驟做法
1把檔案切成 A、B、C…等小區塊，分別算出 Hash(A)、Hash(B)……
2相鄰兩個雜湊值再兩兩配對算雜湊：Hash(Hash(A),Hash(B))……一路往上
3最後只剩一個值：Merkle root
4只要任何一個小區塊被改，往上算出的 Merkle root 就會不一樣

比特幣的區塊裡，通常有成百上千筆交易，就是用 Merkle Tree 把它們的雜湊值層層彙整；要證明「某一筆交易確實在這個區塊裡」，只需要提供一小串（例如 4 個）雜湊值組成的「Merkle 路徑」，不用把整個區塊的資料都攤開來對。

✋ 動手做：先感受雪崩效應，再填樹狀圖

讓學生用線上 SHA-256 工具（emn178 線上工具 ↗）自己輸入一段文字算出雜湊值，再故意改一個字元重算，親眼看到結果整個大不相同（雪崩效應），對雜湊「一改全變」有直覺以後，再回頭把這個直覺套進樹狀結構。

這是一棵「活的」Merkle Tree：在下面四個資料欄位打字，上面的雜湊值會即時一層層算出來（滑鼠移到雜湊值上可以看完整的一串）。

操作步驟：

  1. 在最下面「資料 A」「資料 B」「資料 C」「資料 D」四個欄位，分別打入任意不同的文字（一句話、隨便打幾個字都可以）。
  2. 每打一個字，該欄位下方就會即時顯示這段內容算出來的 SHA-256 雜湊值 Hash(A)～Hash(D)。
  3. 上一層的 H(A,B) 會自動把 Hash(A) 和 Hash(B) 這兩串雜湊值接在一起、再雜湊一次；H(C,D) 同樣的方式把 Hash(C)、Hash(D) 接起來雜湊。
  4. 最上層的 Merkle Root，則是把 H(A,B) 和 H(C,D) 接起來再雜湊一次，變成代表整棵樹的唯一一個值。
  5. 四格都填好之後，回頭只改「資料 A」裡的一個字：你會看到 Hash(A)、H(A,B)、Merkle Root 這條路徑上的框框都亮起來、值也全部跟著變了（雪崩效應一路往上蔓延）——但完全沒被動到的「資料 C」「資料 D」和 H(C,D) 會保持不變、不會亮起來。
  6. 這正好呼應前面說的：Merkle Tree 只要一路往上比對「亮起來的那條路徑」，就能知道是哪一小塊資料被動過手腳，不用重新雜湊整份資料。

04雜湊的實際應用：密碼是怎麼被存起來的？

你登入網站輸入的密碼，資料庫裡通常不會直接存這串文字，而是存這段文字的雜湊值。你輸入密碼時，網站會即時把你輸入的內容算成雜湊值，拿去跟資料庫裡存的雜湊值比對，一樣就代表密碼正確 —— 全程都不需要把「明碼密碼」存在任何地方。

🤔 為什麼這樣比較安全？

就算資料庫真的被駭客整包偷走，駭客拿到的也只是一串雜湊值，而不是明碼密碼。因為雜湊「一改全變」（雪崩效應）又幾乎不可能反推回原文，駭客很難直接從雜湊值算回你的密碼 —— 真正上線的系統還會多加一道「加鹽（salt）」，這個我們會在單元 9 再深入討論。
